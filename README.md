# 进程内规则灰度执行器

单服务、单规则的进程内灰度执行器。构造时注入正式版规则与单调时钟（秒）；
规则为本地函数，接收请求内容，返回是否命中或抛出异常（命中不算执行错误）。

## 接口

- `GrayExecutor(stable_rule, clock)`：`clock` 为返回秒的可调用对象。
- `publish(rule) -> int`：发布候选规则，返回唯一代次；先结算旧状态再替换候选。
- `inspect(payload, bucket) -> InspectOutcome`：同步检查一次，`bucket ∈ [0, 99]`；
  返回实际执行的代次、命中结果或执行异常。
- `state() -> StateView`：正式代次、候选代次、候选阶段（gray/draining/fused）、
  候选在途检查数。

## 语义

- 每次发布开启 900 秒灰度窗口，窗口内 `bucket < 10` 走健康候选，其余走正式版。
- 截止后关闭灰度入口并排空：在途候选检查全部提交且候选仍健康才晋级。
- 仅候选结果计入错误率：按提交时间统计最近 300 秒精确滚动窗口
  （左开右闭），异常占比严格大于 1% 立即熔断，不可自动恢复。
- 被替换或熔断的候选永久失去晋级资格，迟到结果不影响其他代次。
- 规则执行不持有状态锁；分流、提交、publish、state 各自为可线性化事件，
  每个事件先结算当前时刻（移除过期样本 → 熔断判定 → 到期晋级）。

## 运行

```bash
python3 -m unittest discover -s tests -v   # 或 pytest
```

测试使用可控假时钟与同步事件构造交错，不依赖真实等待。
